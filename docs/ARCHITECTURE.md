# Architecture

## What the product is

A Hebrew conversation counterpart for a **prerecorded mission video**. A
trainee watches the recording in a completely separate player and talks to
a UAV operator while interpreting it.

The only connection to the video is the authored timeline and the elapsed
clock. No integration, no playback position, no vision. The trainer starts
the video and the exercise by hand at roughly the same moment.

**The recording is immutable.** Trainee speech cannot change imagery,
camera motion, vehicle behaviour or altitude. This is not a flight
simulator or a branching world.

That constraint is what shapes everything below: the engine does not
*simulate a world*, it *reveals authored facts on schedule* while tracking
what the conversation has established.

---

## Layers

```
ui/index.html            trainer console (HTTP + SSE + WebSocket only)
        |
api/                     HTTP boundary, lifecycle endpoints, persistence
        |
sim/session.py           ONE domain loop, shared by every channel
   ├─ sim/exercise.py    facts, timing, owed reports
   ├─ sim/turns.py       one agent turn
   └─ api/voice.py       transport only
      api/live_voice.py  transport only
        |
tools/                   read facts, manage agreements. Nothing writes the world.
        |
core/                    PURE: no LLM, no network, no I/O, no clock
```

`core/` purity is enforced by a test that walks imports. Without it the
layering degrades within weeks, and with it the whole domain is testable
with no API key.

## The structural decision

**Revelation and delivery are separate.**

```
Exercise.advance()    pure bookkeeping. Reveals events, queues reports.
                      No awaits. Runs every 250ms.
Session._speak_loop   takes one owed report and says it. Blocks for
                      seconds on the model and the speaker.
```

An event becomes known at its authored time even while the operator is
mid-transmission, the trainee is talking, or the crew is handing over. Only
the *report* waits.

This was the main defect in the previous version: one lock covered both, so
a slow model call stalled the timeline, and an event authored for T+480 was
not noticed until whatever was being said finished. A test asserts
`advance()` is synchronous, so the coupling cannot be reintroduced by
accident.

A queued report is **re-checked for relevance** at delivery and marked
reported only once it actually was — a pause or an interruption retries it
rather than silently counting it done.

## Three authored sources

| Source | Form | Holds |
|---|---|---|
| Global context | `context/*.md` | reusable professional knowledge |
| Timeline | `.xlsx` / `.csv` | what happens during the recording |
| Mission state | `missions/*.yaml` | who, where, this crew's behaviour |

Authoring details: [AUTHORING.md](AUTHORING.md).

### The timeline is a fact store, not a queue

`core/timeline.py` answers "what is true now" by folding revealed events,
not by looking up the latest one:

| Type | Semantics |
|---|---|
| `point` | An occurrence. Never *current* afterwards — recalled in the past tense. |
| `persistent` | True until a later event supersedes the same key. |
| `interval` | Current only inside `[start, end)`. Then expired. |
| `handover` | Blocks ordinary conversation for its duration. |

Facts between events stay queryable, which is why this cannot be a list of
lines to announce.

Authored uncertainty survives: a visual observation is not an
identification, and the operator describes rather than concludes.

### No future leaks

`Timeline.revealed(elapsed)` is the **only** accessor that yields
operator-visible text, and it is bounded by elapsed time. Author-facing
`description`, private notes, the schedule and future events have no path
to a prompt.

The exclusion is structural rather than a rule each caller remembers.
Tests assert it through the prompt **and every tool**, since the Live path
reaches tools directly.

## Runtime conversation state

Not a fourth author input — generated by the dialogue.

`core/conversation_state.py` tracks contact, briefing stage, what the
trainee shared, and when each side last spoke.

Two things live in code rather than the prompt:

**Addressing.** The convention is addressee-then-caller on establishing or
re-establishing contact, and *not* on every transmission. Whether this
transmission is a re-establishment is a fact about elapsed silence, so code
decides it and the prompt is told the answer. Default threshold 30 seconds
— an initial tuning value, not an asserted rule.

**Crew availability.** Enforced from the timeline. "Do not reply normally"
is exactly the instruction a model drops under pressure.

### Commitments are code

`core/commitments.py`. The LLM interprets "tell me about every vehicle";
code stores, matches and executes it against authored tags and entity ids.

Given three authored vehicle appearances where one is proactive by default,
one agreement covers the later two. Supports narrowing, replacing and
cancelling. A baseline `required` event that is also covered produces
**one** report.

Agreements default to future events — agreeing to watch is not a request to
recap. Registering requires actual agreement: a request the operator
clarified or pushed back on must not silently become a commitment.

## Lifecycle

```
PREPARING --ready--> READY (t=0) --start--> RUNNING <--> PAUSED
                                               |
any state ------------------------------------ v ENDED
```

Preparation takes time — validating a timeline, connecting a voice socket —
and if the clock ran during it, that setup would become mission time and
the exercise would be out of step with the video before the trainer pressed
play. **Elapsed time is exactly zero until Start.**

**Real time only.** No speed control: accelerating mission time would
desynchronise it from the video. `sim/clock.py` holds a `VirtualClock` for
tests, mirroring the full lifecycle.

**Pause** freezes mission time, stops revelation, and bumps a generation
counter so a model call already in flight cannot speak into a paused
exercise when it returns. Facts, history and commitments survive. **Resume**
drops reports that went stale rather than delivering a burst.

**End** is explicit and automatic at the authored duration.

## Channels

Text, the ElevenLabs cascade and Gemini Live all drive `sim/session.py`.
Only audio transport differs.

The previous version let `api/live_voice.py` reimplement the domain layer.
It omitted a whole tool, never gave the procedure checker its context, and
ran a second trigger loop against the same bookkeeping — so a once-only
event could fire twice. Tests now assert no channel module contains
`select_firing` or its own trigger loop, and that the Live tool
declarations match the real tool set by name.

### A real difference, kept

| | ElevenLabs cascade | Gemini Live |
|---|---|---|
| Shape | STT → agent → TTS | one model hears and speaks |
| Extra key | `ELEVENLABS_API_KEY` | none |
| Pacing | the delivery plan applies | the model's own prosody |
| Vocabulary hints | yes, from the mission | not supported by the API |

Gemini Live controls its own pauses, so authored stalls do not apply there.
That is a genuine difference in feel, not something to claim away.

## Persistence

SQLite behind a repository interface. Single trainer, single process.

| Table | Holds |
|---|---|
| `sessions` | mission, channel, status, timing |
| `utterances` | what was **actually said**, by either side |
| `revealed_events` | what became known, and each report's disposition |
| `agreements` | what was agreed, narrowed or cancelled |

All three channels write identically. Previously neither voice path wrote
anything — a Gemini Live session left no transcript at all, so `GET
/review` returned empty and the session could not be debriefed.

**Undelivered output is never stored as heard.** An abandoned turn records
empty text with a status and the intended text separately, so a debrief
cannot show words the trainee did not hear.

**An honest limit.** With native streaming voice the model generates audio
and transcribes its own speech. If the trainee talks over it, what they
actually *heard* can only be estimated. Those rows carry `delivery =
"streamed"` to mark the distinction.

Schema migration is per column: `CREATE TABLE IF NOT EXISTS` leaves an
older table alone, which silently broke every insert on the first run after
this refactor.

## Tools

| Tool | Purpose |
|---|---|
| `current_information` | facts the operator can see now |
| `recall_observation` | revealed facts from earlier, flagged current or past |
| `agree_to_report` | register an agreement (returns a **count**, never the events) |
| `cancel_reporting` | drop one or all agreements |
| `listed_commitments` | what is currently agreed |
| `cannot_comply` | the authored reason something is impossible |

**Nothing writes world facts.** `set_parameter` is gone: the recording is
immutable, so a tool that let the model change altitude or camera angle
manufactured a world the video does not show, and the trainee would then be
reasoning about fiction.

`check_procedure` is also gone. It matched keywords and presented the
result as professional assessment, and the session and tool paths fed it
different context. Procedure is professional guidance in `context/*.md`,
not a keyword check.

There is no "read before every number" round trip. The prompt already
carries a fresh authoritative snapshot, so requiring a call to quote a
figure it was just handed was wasted latency. Grounding is unchanged:
figures come from authored facts either way.

## Prompt composition

`agent/prompts.py`. Precedence, in one place so it cannot drift into
contradiction:

1. identity and hard rules (confidentiality, no invented facts)
2. global context — the user's own doctrine, verbatim
3. mission metadata
4. live state — revealed facts, addressing, crew availability
5. author overrides — last, so a mission can countermand the above

The previous version asserted doctrine that had been invented rather than
supplied: a blanket callsign rule, a brevity vocabulary, transmission
formats, and "read before every number" in four places. One piece
contradicted the code — the prompt demanded callsigns every line while the
checker enforced them only on the first. All of it is gone.

---

## Deliberately not here

No video player, vision model, controller persona, scenario editor,
automatic grading, microservices, multi-user auth, RAG, or simulator
framework. Single-trainer prototype.

Local speech and air-gap proof are deferred; the provider interfaces remain
as swap points.
